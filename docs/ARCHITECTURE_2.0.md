# 🏛️ Thakur Bites Platform 2.0 — Architecture & Security Manual

## 1. System Overview & Invariant Philosophy

**Thakur Bites Platform 2.0** is an enterprise-grade digital canteen operating system designed specifically for the TCET engineering campus. It powers three synchronized interfaces backed by a single authoritative cloud backend:

1. **📱 Flutter Customer App**: For students, visitors, and verified teachers/faculty.
2. **🍳 Staff Operations Hub**: Web workstation portal for Kitchen KDS, Pickup Dispatch, Menu & Inventory Control, Owner Executive Dashboard, and Developer Security Cockpit.
3. **📺 Standalone 4K TV Board (`web_tv/`)**: Zero-authentication, high-contrast order dispatch monitor for cafeteria wall TVs.

## 3. Anti-Starvation Priority Queue Scheduling

### Effective Priority Formula
$$P_{\text{eff}} = P_{\text{base}} + (\text{MinutesWaiting} \times 5)$$

- **Base Priorities ($P_{\text{base}}$)**:
  - Visitor: `0` (Starts at 0 pts)
  - Student: `100` (Starts at 100 pts)
  - Faculty / Teacher: `200` (Starts at 200 pts)
  - VIP / Emergency: `300` (Starts at 300 pts)
- **Anti-Starvation Aging**: Every minute a student ticket waits in queue, it gains $+5$ points. After 20 minutes of waiting, a student ticket reaches 200 points, equaling a fresh faculty ticket and preventing queue stagnation.
- **Fairness Limiter**: Faculty accounts can have at most **1 concurrent active priority ticket**. Subsequent simultaneous orders drop down to standard priority (Level 1).
- **Physical Inventory Independence**: Priority affects ticket preparation ordering in the Kitchen KDS only. It **never** retroactively takes physical stock away from already-confirmed student orders.

## 4. Workstation Shift PINs & Hardware Device Binding

- **Salted SHA-256 Hashes**: 6-digit CSPRNG PINs are generated by managers for specific roles (`kitchen`, `pickup`, `cashier`) and shifts (`MORNING`, `AFTERNOON`, `FULL_DAY`). Only salted hashes are stored in Firestore; raw PINs are never persisted.
- **Device Fingerprint Binding**: Binds each PIN to designated counter hardware tablet UUIDs (`tb_workstation_device_id`), blocking unauthorized personal device access.
- **Brute-Force Lockout Defense**: 5 consecutive failed PIN attempts locks workstation login for 15 minutes.

## 5. TV Display Zero-PII Projection & Audio Chime

- **Isolated App Architecture (`web_tv/`)**: Standalone web application with zero authentication dependencies.
- **Resilient 3-State Stream Controller**:
  1. 🟢 **LIVE DISPATCH**: Real-time 2-column split (Preparing vs Ready).
  2. 🟡 **RECONNECTING**: Displays non-intrusive status bar and retains cached tickets if network blips.
  3. 🔴 **CANTEEN STANDBY**: Clean off-hours graphic when queue is empty.
- **Zero-PII Security**: Exposes ONLY token numbers (`TB-042`), preparation status, and ETAs. Strips student names, roll numbers, phone numbers, and payment details.
- **Web Audio API Chime**: Synthesized two-tone bell chime (800Hz $\to$ 1060Hz) fires when a token enters `READY` state.

## 6. Executive Owner Console & Predictive Stockout Forecaster

- **Integer Paise Financials**: Strict double-entry accounting where $\text{Gross Revenue} = \text{Digital UPI} + \text{Cash Counter}$.
- **Predictive Inventory Run-Rate Formula**:
  $$\text{BurnRate} = \frac{\text{UnitsSoldToday}}{\text{HoursElapsedToday}}$$
  $$\text{HoursRemaining} = \frac{\text{AvailableStock}}{\text{BurnRate}}$$
- **Urgent Restock Warning**: Automatically triggered when $\text{HoursRemaining} < 1.5\text{ hours}$ and stock is non-zero.
- **Campus Feature Flags**: Real-time authoritative switches for Mobile Ordering, Faculty Priority, Cash Counter, and Rush ETA multipliers (1.0x to 2.5x).
